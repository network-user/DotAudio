# План закрытия обратной связи по Whisper

Документ фиксирует, какие замечания уже закрыты в текущей рабочей версии, а
какие требуют проверки на физических компьютерах. Цель - не скрывать долгую
загрузку за «зависшим» процентом и не терять обычную расшифровку, если
ускоритель или diarization недоступны.

## Матрица проблем

| Проблема | Реализация | Проверка готовности |
|---|---|---|
| Выбор модели и выгрузка в GPU | `hardware.py` + `adapt.py` оценивают RAM/VRAM, `engine.py` делает preflight и выбирает безопасный compute type; устройство и модель задаются в UI | Нехватка памяти объясняется до запуска; успешный runtime-device показывается пользователю |
| Зависание на 55% при загрузке | На неизвестных этапах используется indeterminate progress; callback показывает фазу загрузки, а не ложный процент | 4060 не остаётся на постоянных 55%; при ошибке видна причина и доступен CPU fallback |
| Медленный CPU | Подбор профиля по железу, ограниченные Live-окна, bounded queues, отдельная быстрая модель черновика и отказ от лишних word timestamps в Live | На слабом ноутбуке приложение не блокирует GUI; скорость и качество замеряются отдельно на целевых машинах |
| Языки и перевод | Добавлен `multilingual`/`auto` для распознавания; `EN → RU` остаётся локальным OPUS-MT, остальные пары подключаются отдельной MT-моделью | Исходный язык не подменяется переводом; перевод запускается явно |
| Пользовательские pretrained-модели | `model_registry.py` принимает проверенные локальные каталоги CTranslate2 с явной парой языков; произвольные файлы и запуск кода отклоняются | Модель импортируется из Settings, проходит валидацию и появляется в каталоге |
| Технологический стек | Приложение использует Python core + PySide6/Qt Quick; Electron не используется | Документация и ответ пользователю не называют проект Electron-приложением |
| Непонятные зависания | `diag.py`, структурированные статусы setup/model/diarization, actual device, elapsed time и отмена; для backend без процента - честная анимация | По каждой долгой операции видны фаза, компонент, сообщение и доступное действие |
| Prompt, короткие чанки, шум | Термины из локального словаря попадают в ограниченный Whisper `initial_prompt`; Live-окно настраивается; добавлены опциональные stationary-noise gate и high-pass | Prompt не заменяет аудио и ограничен; шумоподавление выключено по умолчанию и не портит исходный файл |
| GPU-транскрибация без голосов | Перед NeMo освобождается кеш Whisper; diarization использует фактическое устройство, пробует CPU fallback, а при полном отказе сохраняет текст без меток голосов | GPU-ошибка не обнуляет транскрипт; UI объясняет, почему голоса недоступны |
| Потеря файла при быстром росте | `watch_folder.py` ждёт два одинаковых опроса размера перед отправкой файла | Файл не уходит в обработку на первом незавершённом изменении |

## Что осталось проверить вручную

1. NVIDIA 4060 с актуальным драйвером: `tiny/base/small`, CUDA и CPU fallback,
   загрузка из холодного кеша.
2. Слабый CPU-ноутбук: 10 минут Live, остановка, отмена и переполнение очереди.
3. Медиа с двумя-тремя говорящими на GPU: голоса должны появляться, а при
   нехватке VRAM - сохраняться хотя бы текстовые сегменты.
4. Китайская/английская речь: распознавание в `multilingual`, затем явный
   перевод установленной пользовательской моделью.
5. Реальные микрофон, WASAPI loopback, FFmpeg и ручной запуск на Windows.
   Linux/macOS пока не заявляются как проверенный end-to-end паритет.

Автоматические тесты не скачивают модели и не включают микрофон. Команды и
ограничения запуска описаны в README и AGENTS.md.
