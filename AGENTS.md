# DotAudio: инструкции агентам

## Контекст

Настольное приложение к статье на Хабре о Whisper.
Последнее указание пользователя в исходной сессии - подготовить основу
для передачи другой модели. Код не считается готовым продуктом.
Перед продолжением прочитай `docs/HANDOFF.md` и `docs/PRODUCT.md`.

## Профиль проекта

- Тип: desktop-app с Python core и необязательным HTTP-сервисом.
- Аудитория: пока internal; будущая демонстрация в статье.
- Дистрибуция: local-only, установщик ещё не реализован.
- Первая платформа: Windows. Остальные платформы не проверены.
- Runtime: Python >=3.12,<3.14, Qt Quick через PySide6.
- `pyproject.toml` - источник правды по зависимостям и entrypoints.
- Git-репозиторий и remote на момент создания не инициализированы.

## Запуск и проверки

Все команды выполнять из корня DotAudio в собственной `.venv`.
Не менять окружения соседних проектов.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e '.[dev,server]'
.\.venv\Scripts\dotaudio.exe
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check src tests
```

Без editable-установки использовать `PYTHONPATH=src` и `python -m dotaudio`.
Для QML smoke-test задать `QT_QPA_PLATFORM=offscreen` и передать
`--smoke-test --data-dir .local-check`.
Не скачивать модели и не включать микрофон в обычных unit-тестах.
Сборка установщика ещё не настроена; не выдумывать команду build.

## Принципы реализации

- Не помещать inference, скачивание модели и декодирование в GUI thread.
- Не обращаться к QML-объектам из worker threads; использовать Qt signals.
- Сохранять Qt-free границу engine/capture/storage/transcripts.
- Таймкоды сегментов: конечные секунды, start >= 0, end >= start.
- Различать stop с сохранением хвоста и cancel без автовставки.
- Не допускать повторного завершения сессии и потери аудио без статуса.
- Ограничивать очереди и кеш модели, измерять рост памяти.
- В Live предварительный текст держать только в памяти; в SQLite писать один
  финальный сегмент, а устаревшие preview заменять свежим снимком.
- В Live при отставании модели вытеснять неначатую фразу, не убивать сессию.
  Диктовка сохраняет строгую очередь и ошибку при переполнении.
- Принудительная остановка на острове должна снимать busy, если native decode
  не вернул управление.
- Не отправлять Enter после автовставки. Проверять целевое окно.
- Цвета, кегли, скругления, длительности и кривые брать из `qml/Theme.js`,
 а не задавать в компонентах. Системные `Switch`, `ComboBox` и подобные
 использовать только через обёртки проекта.
- В живом субтитре не пересобирать фразу целиком: совпадающий префикс
 сохраняется, анимируются только новые слова и их позиции.
- Не подменять фактические уровни аудио и результаты демонстрационными.
- Поддержку устройства/ОС и скорость заявлять после реальной проверки.
- Конфигурация серверного режима не означает готовность public API.
- В Q_PROPERTY не обращаться к диску, сети и подпроцессам: интерфейс читает
  свойства на каждой перерисовке. Готовность модели и опрос служб считать в
  воркере и отдавать готовым значением.
- Языковая модель к расшифровке - явное действие пользователя. Не переписывать
  расшифровку её ответом и не запускать её сама по себе.
- Длинную запись отдавать модели через части и их выжимки, а не обрезкой
  контекста: выжимка считается один раз и живёт в базе рядом с записью.
- Готовые нативные сборки llama.cpp собраны не под каждый процессор и не под
  каждую версию Python. Пригодность проверять, а не заявлять; при отказе
  сборки предлагать возврат к варианту «Процессор».
